# WB Джем: полный перечень публичных read-only API

Документ сверяется с публичной документацией WB API, разделом «Аналитика и данные», и описывает только официально документированные методы Seller API. Проверено 18.11.2026.

Важно различать функции подписки в кабинете WB Partners и методы публичного Seller API. Подписка «Джем» включает дополнительные отчёты и инструменты в интерфейсе продавца, но не каждый такой отчёт имеет публичный API-метод. Мы не используем внутренние недокументированные HTTP endpoints кабинета.

## Публичные методы поисковой аналитики «Джем»

Все пять методов ниже используют HTTP POST, но только возвращают аналитику. Параметры запроса передаются целиком, без потери фильтров.

| Метод WB | MCP-инструмент | Назначение |
|---|---|---|
| `POST /api/v2/search-report/report` | `wb_search_report` | Главная страница отчёта: видимость, позиции, переходы, группы |
| `POST /api/v2/search-report/table/groups` | `wb_search_table_groups` | Пагинация по группам предмет/бренд/ярлык |
| `POST /api/v2/search-report/table/details` | `wb_search_table_details` | Пагинация по товарам внутри группы или по фильтру nmIds |
| `POST /api/v2/search-report/product/search-texts` | `wb_search_texts` | Поисковые фразы конкретных товаров |
| `POST /api/v2/search-report/product/orders` | `wb_search_product_orders` | Заказы и позиции товара по поисковым фразам, максимум 7 дней |

В главном отчёте доступны периоды сравнения, фильтры по nmIds/subjectIds/brandNames/tagIds, кластеры позиций, сортировка, пагинация и переключатели прямых запросов с подменными артикулами и поисковых фраз без подмены. В методе поисковых фраз доступны пять режимов выбора топа: переходы в карточку, добавления в корзину, конверсия в корзину, заказы и конверсия в заказ. Для тарифов «Продвинутый» и «Премиальный» WB указывает максимум 100 запросов вместо стандартных 30; тот же верхний предел учтён для метода заказов по поисковым фразам.

## Воронка продаж и расширенная история

| Метод WB | MCP-инструмент | Назначение |
|---|---|---|
| `POST /api/analytics/v3/sales-funnel/products` | `wb_analytics_detail` | Воронка по товарам за период, сравнение периодов, фильтры и пагинация |
| `POST /api/analytics/v3/sales-funnel/products/history` | `wb_analytics_history` | История по товарам по дням/неделям, максимум последняя неделя |
| `POST /api/analytics/v3/sales-funnel/grouped/history` | `wb_analytics_grouped_history` | История групп по предметам, брендам и ярлыкам |

Для длинной истории WB предлагает CSV-выгрузки Seller Analytics. Именно эти выгрузки позволяют получить данные воронки за период до года с подпиской «Джем».

## CSV-отчёты Seller Analytics

У WB есть общий асинхронный конвейер: создать задание на отчёт, прочитать список/статус, при ошибке повторить генерацию, скачать ZIP с CSV. Создание задания и повторная генерация не меняют карточки, цены, заказы, остатки, рекламу или настройки магазина: это операции подготовки аналитического файла.

| Метод WB | MCP-инструмент | Назначение |
|---|---|---|
| `POST /api/v2/nm-report/downloads` | `wb_analytics_csv_report_create` | Запустить формирование аналитического отчёта |
| `GET /api/v2/nm-report/downloads` | `wb_analytics_csv_reports_list` | Получить статусы и метаданные отчётов |
| `POST /api/v2/nm-report/downloads/retry` | `wb_analytics_csv_report_retry` | Повторить формирование отчёта со статусом FAILED |
| `GET /api/v2/nm-report/downloads/file/{downloadId}` | `wb_analytics_csv_report_download` | Скачать ZIP и вернуть CSV-файлы как текст |

Поддерживаемые типы отчётов:

| reportType | Данные | Требование |
|---|---|---|
| `DETAIL_HISTORY_REPORT` | Воронка по отдельным артикулам, агрегация день/неделя/месяц | Джем |
| `GROUPED_HISTORY_REPORT` | Воронка по предметам, брендам и ярлыкам | Джем |
| `SEARCH_QUERIES_PREMIUM_REPORT_GROUP` | Поисковая аналитика по группам | Джем |
| `SEARCH_QUERIES_PREMIUM_REPORT_PRODUCT` | Поисковая аналитика по товарам | Джем |
| `SEARCH_QUERIES_PREMIUM_REPORT_TEXT` | Поисковая аналитика по текстам запросов | Джем |
| `STOCK_HISTORY_REPORT_CSV` | История остатков | Доступен без Джема |
| `STOCK_HISTORY_DAILY_CSV` | История остатков по дням | Доступен без Джема |

Для типов отчётов параметры `params` должны соответствовать модели конкретного типа. Примеры и актуальные поля следует сверять с выпадающим описанием `reportType` в документации WB API. MCP-инструмент принимает объект `params` целиком, поэтому новые поля API можно передать без изменения схемы инструмента.

## Подписка

`GET /api/common/v1/subscriptions` доступен через `wb_jam_subscription` и позволяет прочитать состояние подписки.

## Что не следует выдавать за публичный API

В интерфейсе подписки «Джем» также перечислены отчёты «Портрет покупателя», «Анализ ниш», «Календарь событий», «Доходы и расходы», «Юнит-экономика», «Сравнение карточек» и дополнительные инструменты для контента/отзывов. В открытой спецификации Seller API, проверенной для этой сборки, отдельные публичные read endpoints для части этих интерфейсных отчётов не описаны. Поэтому они не объявляются реализованными и не вызываются через неофициальные внутренние маршруты кабинета.

Если WB опубликует эти методы в Seller API, их следует добавить в этот каталог после сверки схемы, авторизации, лимитов и семантики метода. Никакие скрытые/внутренние API кабинета не используются.

## Ограничения и частота

Лимиты различаются по методу и типу токена. Для поисковой аналитики WB указывает, в частности, 3 запроса в минуту для персонального/сервисного/базового с секретом токена и более строгие лимиты для базового токена. Данные части отчётов обновляются раз в 2 часа — это свежесть данных, а не разрешение опрашивать endpoint чаще лимита. Сервер сохраняет общий механизм throttling/retry и не пытается обходить лимиты.
